# Complete slice workflow

1. **Discover and reserve.** Read project instructions, current build plan and previous receipts. Record source revision, dirty state, installed version, execution host, device, dependencies and existing failures. Use an isolated branch/worktree and respect source/device leases. A failed lease read means unavailable, never free.
2. **Define behavior before edits.** Inventory every affected button, field, gesture, nested control, Back/dismiss action and disabled/loading/error state. Give each a stable ID, precondition, action, observable result, deadline/tolerance and evidence method. Link each ID to the same done criterion used for acceptance. Separate observed baseline behavior from desired behavior. Record intentional behavior changes explicitly.
3. **Capture the baseline.** Preserve logs, screenshots, hierarchy, build identity and device settings before modifications. Test the original build under the same conditions as the candidate. Missing hardware/authentication/lease produces BLOCKED, not an inferred pass. Preserve data and state; use disposable fixtures for destructive cases.
4. **Implement narrowly.** Preserve callbacks, public APIs and storage contracts unless changing them is the slice's purpose. Review dependencies, security/secret handling, accessibility, lifecycle/persistence, resource cleanup, failure recovery and concurrency where affected. Keep changes small and reviewable; no unrelated refactor or dependency upgrade.
5. **Verify proportionately.** Build and lint; record existing failures separately. Test logic and failure paths where changed. Check actual pixels and semantic bounds on the target hardware, both orientations, enlarged text, offline/reconnect and persistence where relevant. Source callback comparison supports review but does not prove runtime behavior. Screenshots alone do not pass a criterion.
6. **Integrate and release.** Review the final diff, integrate latest main and repeat affected checks. Allocate versions only in the designated install tree under its claim. Archive the exact APK with revision and SHA-256. Install only under the device lease; restore default HOME after replacement. Avoid data-clearing shortcuts.
7. **Accept and restore.** Record expected versus actual values and PASS/FAIL/BLOCKED/NOT RUN for every criterion. Preserve raw evidence. Restore settings, foreground pane/app, playback and connectivity, then verify restoration. Investigate crashes within a recorded time boundary. Mark DONE only when all required gates pass.
8. **Close and hand off.** Commit source and docs; record build/version/artifact hash, evidence path, remaining failures, next command and prerequisites. Roll back through a reviewed revert and a higher-version release when Android prevents downgrade. Release owned claims. Put reusable methods in the shared skill and project-specific state in project docs.

## S7 application

The pre-edit inventory is `S7-CONTROLS.md`. `s7-source-audit.py` compares extracted callback bodies, and `s7-smoke.py` captures the visual matrix and measures visible tap bounds under a verified lease. Neither script asserts complete behavioral acceptance. PowerStrip can scroll horizontally when enlarged text or a narrow map region exceeds available width; include reachability of its Starlink control in the visual review without toggling physical hardware. Rail and media content scroll when space is insufficient.

Reference standards: [Android accessibility defaults](https://developer.android.com/develop/ui/compose/accessibility/api-defaults), [semantics](https://developer.android.com/develop/ui/compose/accessibility/semantics), [adaptive icons](https://developer.android.com/develop/ui/compose/system/icon_design_adaptive), [small changes](https://google.github.io/eng-practices/review/developer/small-cls.html). S7 is tablet presentation polish, not a claim of automotive-interface certification.
